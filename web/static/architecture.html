Zen Data Engine

Recorded voice-agent calls in, corrected fine-tuning data out — with every caller turn byte-identical to what a real person said, and every change traceable to the rule that justified it.

01The model is a leaf, not a hub

Most agent systems put the model at the centre and hand it capabilities. This one inverts that: the model is the least-privileged component in the building. It receives text, returns JSON, and is destroyed. Every safety property downstream descends from this one decision.

02What happens to one conversation

Each hop is a separate queue row, which is what makes any of it resumable. Repair is a bounded loop, not unbounded retry — and exhausting it is a salvage path rather than a failure.

03Two tiers: a mill, and an engineer above it

The mill is deterministic on purpose — at roughly five model calls per conversation and 1.6M conversations available, an exploratory loop costs an order of magnitude more and gives up reproducibility. But a mill cannot answer why it is failing. That question is unknown-shape, low volume, and high value, which is exactly what agency is for.

04What the design refuses to do

Provenance

Caller turns are never rewritten

Every user turn is byte-identical to the recording, verified by per-turn SHA-256. Only the agent's side is ever corrected.

Grounding

No invented tool calls

Source calls are hashed at bind time, so a claim can be checked against the record rather than trusted. Added calls are stripped and the turn marked as lacking evidence.

Independence

The verifier reads no argument

Roles exchange artifacts, not reasoning. The judge and repairer see the case file; the first-pass verifier is deliberately blind, or it would agree with the case rather than judge the output.

Correction

Coerce, don't reject

Where Python knows the right answer it overrules the model and records doing so — fifteen named markers, each an audit trail rather than a silent fix.

Reproducibility

The model never picks the next step

Stage routing is a dictionary and an if-chain. Identical input takes an identical path, which is what makes the corpus auditable.

Attribution

Every change cites a rule

Corrections resolve to an axis → sub-axis → variant path from the governed eval taxonomy, by name. A rewrite that cannot name the rule it enforces is reverted.

Instrumentation

A silent instrument is worse than none

Every model call is recorded — role, model, latency, tokens, retries. Twice a monitor reported confidently wrong state, so the swallow that hid the fault is now diagnosable rather than absolute.

Separation

Synthetic data never mixes

Replayed trajectories carry simulated caller turns. They ship in their own file, every synthetic turn flagged, stamped NOT_BYTE_FAITHFUL.

05Five stores, one job each

Separation is deliberate. Assurance lives outside the pipeline it audits, and instrumentation stays off the queue's hot write path so it can never slow down what it measures.
